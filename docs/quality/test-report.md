## 3. Defects Found and Fixed in This Pass

Each fix has a test that fails without it, and that failure was observed during this pass.

| ID | Severity | Area | Defect | Fix | Regression test |
|---|---|---|---|---|---|
| DEF-01 | High | Secrets | The working copy of the tracked `backend/.env.example` held real values: the database connection string with its password, the Supabase anon key, JWT secret and service-role key, and the app secret key. A routine `git add` would have published them. `git log -S` over all 15 commits finds none of them, so they were never committed. This also caused the one pre-existing test failure (`test_env_example_values_load`). | Values blanked in `.env.example`. The real values remain in the git-ignored `backend/.env`. | `tests/unit/test_config.py::test_env_example_contains_no_real_secrets` fails on any credential-shaped or filled sensitive value. It was verified by injecting a value. |
| DEF-02 | High | Database RLS | `message_attachments_select_member` read `messages.suppressed_at`, a column clients are deliberately not granted. Postgres checks column grants inside policy sub-queries, so every attachment query by a conversation member failed with "permission denied for table messages". The backend uses a privileged role and was unaffected, but the policy, which is the last line of defence for direct database access, did not work. It also ignored "delete for me". | Migration `20261113000002_fix_attachment_select_policy`. The check moves into the `security definer` helper `private.can_see_attachment_message()`, which also honours `message_hides`. | `supabase/tests/database/05_attachments_and_group_members_rls.test.sql`. It failed with exactly that error before the migration existed. |
| DEF-03 | Medium | Test reliability | Two flaky frontend tests. The sign-in test read the `/users/me` call before the SPA had made it. The SMS compose test clicked a "Review and send" button node that re-rendered while the form revalidated. Each failed once under a full parallel run and passed alone. | The tests now wait for the request and re-query the button at click time. | Every later full Vitest run passed, including the 2 made after both fixes were in place (one is the final run in section 1). |
| DEF-04 | Medium | Test harness | Browser contexts opened for a second person were never closed. With one worker they all stayed signed in, polling and holding WebSockets. Later specs slowed, and one navigation timed out after 90 s. | An auto fixture closes every extra context after each spec. | Full-suite time fell from 926 s to 267 s, and the timeout is gone in two consecutive runs. |
| GAP-01 | Medium | Database RLS | `message_attachments` and `contact_group_members` had RLS enabled but no RLS tests (testing rules: every table needs cross-user denial tests). | Test file 05 added. | Same file. |

### Failures seen during the pass that were not product defects

- **Machine sleep during a backend run.** One full run took 5 h 23 min because the computer slept. One request logged `duration_ms: 18495381`, about 5 hours. The next request's 1-hour access token had expired, so `test_chat.py::test_offline_recipient_gets_messages_later_and_sender_learns_of_delivery` got a 401. The file then passed 3 times in a row, and the clean full run in section 1 includes it.
- **Spec errors in the new Playwright specs.** These were wrong selectors, mock output text that differed from what I assumed, and a phone-verification step that raced its own API check. They were corrected in the specs. None indicated a product fault.

## 4. Known Limitations

| Area | Limitation |
|---|---|
| Live SMS | Twilio is never called. Live mode is tested against an in-process fake (`test_sms_live.py`), and the real Twilio sandbox test is skipped without credentials. Real carrier behaviour, delivery receipts per route and Philippine sender-ID registration are not verified. |
| AI | Only the mock provider runs. Bedrock request and response mapping is unit-tested with stubs (`test_ai_providers.py`). No call reaches Bedrock, so output quality and real latency are untested. |
| Auth | A fake Supabase Auth stands in for GoTrue in backend flows and browser tests. Behaviour that differs in real GoTrue (email templates, ES256 key rotation in production, provider rate limits) is not covered. |
| RLS | SQL tests run on PGlite with a Supabase stub (`auth.uid()` from `request.jwt.claims`). They have not been run against a hosted Supabase project. Storage bucket policies are not exercised against real Supabase Storage. |
| Browser suite | Chromium only, one desktop viewport, against the Vite dev server rather than the production bundle. No mobile viewport or 320 px check, no Firefox or WebKit, no automated accessibility scan (axe). Full WCAG conformance needs manual testing with assistive technology. |
| Rate limits | Login, sign-up, resend, reset, phone code, contact search, contact requests, chat send and AI are tested for 429 (backend flows, plus two browser checks). Webhook rate limiting and per-IP limits on SMS sending have no dedicated test. |
| Performance | No load, soak or latency testing was run (`performance-test-plan.md` is not automated). |
| Timing | Simulated delivery takes about 6 s and depends on the 1 s worker poll. Specs allow up to 45 s, so a heavily loaded machine could still time out. Long runs are sensitive to the machine sleeping (access tokens last 1 hour). |
| Dependencies | `npm audit` reports 16 issues (8 moderate, 8 high), all in transitive `minimatch` and `picomatch` used by build and lint tooling. They are not shipped to the browser. They predate this pass; Playwright adds only `playwright-core`. The offered fixes are breaking (`vite@6`). |
| Warnings | Starlette warns that using `httpx` with its test client is deprecated. |

## 6. Recommended Fixes and Next Steps

1. **Rotate the credentials from DEF-01 as a precaution.** They were never committed, but they sat in a tracked file. That covers the database password, the Supabase JWT secret and service-role key, and the app secret key. Rotate them in the Supabase dashboard and update `backend/.env`.
2. **Apply migration `20261113000002`** through the normal migration process (staging first, then production with approval).
3. **Add flow tests for the four uncovered webhook paths** in `test_sms.py` (OD-QA-02): mismatched provider ID, invalid sender number, suppressed sender, and batch reprocessing.
4. **Extend the browser suite.** Add an axe scan per page, a 320 px mobile project, and a run against `vite build` plus `vite preview`. ADL-023 and DEC-UI-MODES-001 list these as open.
5. **Add webhook and SMS-send rate-limit tests**, per user and per IP.
6. **Upgrade the build tooling** when `vite` and `typescript-eslint` releases with patched `picomatch` and `minimatch` are available within the pinned majors. Do not use `npm audit fix --force`.
7. **Run the Twilio sandbox tests** (`test_twilio_test_credentials.py`) once test credentials exist. They use Twilio's test credentials and magic numbers, so no real SMS is sent.

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest --cov=app --cov-branch --cov-report=term --cov-report=json:coverage.json --cov-report=html:htmlcov --junitxml=junit-backend.xml

# Frontend: tests, coverage, JSON results
cd ..\frontend
npx vitest --run --coverage --coverage.reporter=text-summary --coverage.reporter=json-summary --coverage.reporter=html --coverage.reportsDirectory=coverage --reporter=default --reporter=json --outputFile.json=coverage/vitest-results.json

# Live-stack service tests and browser suite
cd ..
.\scripts\e2e-local.ps1
.\scripts\e2e-browser.ps1
.\scripts\e2e-summary.ps1          # compact pass/fail table

# Database SQL and RLS tests
cd supabase\tools; npm test; cd ..\..

# Regenerate the catalogue from the result files
backend\.venv\Scripts\python.exe scripts\test_catalogue.py
```
